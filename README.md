# ResumeTap

> **纯 AI 驱动**的简历速筛桌面应用。先选定要招的岗位，导入简历后由你自己的 AI 逐份评估，给出**优点、缺点、评分理由**，你只需按 `喜欢 / 不合适 / 稍后` 做决定。

**需要自备 AI 接口**（任何 OpenAI 兼容服务）。简历只发送到你填写的接口，其余数据全部留在本机。

## 快速开始

### 方式一：下载便携版（推荐）

从 [Releases](https://github.com/iATOEL/ResumeTap/releases/latest) 下载
`ResumeTap-v3.1.1-win64.zip`，解压到任意位置（桌面、U 盘都行），双击 `ResumeTap.exe`。

解压后的目录结构：

```
ResumeTap/
├── ResumeTap.exe          启动器
├── _internal/             运行依赖（请勿删除）
├── ui/                    界面文件，可自行调整样式
├── assets/                图标等资源
├── samples/               示例简历
├── data/                  你的数据（配置 / 数据库 / 简历 / 导出 / 日志）
├── config.example.yaml    配置参考
├── README.txt             使用说明
└── LICENSE
```

**绿色版特性**：所有数据都写在 `data/` 内，整个文件夹可以随意拷贝到另一台电脑继续用；
卸载只需删掉文件夹，不在系统里留任何东西。

> 不需要安装 Python 或任何运行环境。Windows 10/11 自带所需组件。
> 源码与构建脚本在仓库里，发布包只通过 Releases 分发（zip 不进版本库）。

### 方式二：从源码运行

```bash
python -m venv .venv
.venv/Scripts/pip.exe install -r requirements.txt
.venv/Scripts/python.exe run_app.py
```

调试模式（打开开发者工具）：

```bash
RESUME_GACHA_DEBUG=1 .venv/Scripts/python.exe run_app.py
```

## 核心流程

### 第一步：选择招聘岗位

打开应用后先选定要招的岗位。内置 **27 类岗位，按 6 个行业分组**：

| 分组 | 岗位 |
|---|---|
| 技术研发 | 后端 / 前端 / 全栈 / 数据分析 / 算法 / 测试 / 运维 SRE / 安全风控 |
| 产品设计 | 产品经理 / UI 视觉 / 交互 UX |
| 运营市场 | 品牌营销 / 运营 / 销售商务 / 客服成功 / 媒体内容 |
| 职能支持 | 人力资源 / 财务会计 / 法务 |
| 工程制造 | 机械硬件 / 生产制造 / 供应链采购 / 物流仓储 / 建筑土木 |
| 医疗教育 | 医疗护理 / 教师教研 |

列表里没有的岗位可以点 **「自定义岗位…」**：填岗位名称 + 该岗位最看重的关键词，
系统按你的关键词计算岗位匹配度。

系统会按所选岗位的技能画像打分。**不选岗位就不能开始速筛**——把不同岗位的简历混在一起筛，
评分是没有意义的。

顶部随时可以切换岗位，切换后全库自动重新评分。

### 第二步：逐份速筛

选定岗位后，系统按综合分从高到低排队，一次只呈现一份简历：

```
┌──────────────────────────────────────────┐
│  速筛进度  3 / 12              剩余 9 份   │
│  ████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │
├──────────────────────────────────────────┤
│  (张)              [SSR] [通过]           │
│                                          │
│  张伟  后端开发                    91.2 分 │
│  12.1 年经验 · 本科 · 浙江大学 · C9        │
│                                          │
│  整体竞争力强，建议优先沟通。技能栈扎实…    │
│                                          │
│  优点 ✓              不足 !               │
│  ✓ 技能栈扎实，命中 19 项  ! 未发现明显短板 │
│  ✓ 12.1 年相关经验                        │
│  ✓ 教育背景突出：本科·浙江大学（C9）        │
│                                          │
│  技能 100 | 经验 100 | 学历 100 | …       │
│  [微服务] [Java] [Kafka] [Redis]         │
│                                          │
│  ✕ 不合适      ↓ 稍后      ♥ 喜欢         │
└──────────────────────────────────────────┘
```

- **联系方式**：识别到的手机号与邮箱直接显示在卡片上（未识别会明确标注）。
- **教育经历**：逐段列出毕业院校全名、院校层级（C9/985/211/双一流/海外/普通/专科）、学历、专业、起止时间。
- **优点 / 不足**由 AI 依据简历事实逐条给出，并写明判断依据，不是固定模板。
- **切换岗位不会冲掉已有结果**：切换后保留已有分数与评语，只更新岗位标签；要按新岗位重评需重新排队。
- 三档操作：`喜欢`（进入候选）、`不合适`（排除）、`稍后`（暂不决定）。
- 点卡片任意位置可打开完整详情（五维得分与理由、优缺点、教育经历、技能章节、项目经历、简历原文）。
- 全部看完后进入完成页，可一键导出。

## AI 配置与评估队列

### 第一步：配置 AI（必需）

**设置 → AI 评估**：

| 字段 | 说明 |
|---|---|
| 启用 AI 评估 | 总开关，必须勾选并填 Key |
| 接口地址 | `https://api.openai.com/v1` 这类 Base URL，自动补 `/chat/completions` |
| API Key | 仅写入本机 `config.yaml` |
| 模型 | 如 `gpt-4o-mini`、`deepseek-chat` |
| 超时 | 单次请求秒数，默认 90 |
| 导入后自动开始评估 | 开：导入即评估；关：需手动点"开始评估" |

填完点 **「测试连接」** 验证。支持任何 OpenAI 兼容接口，包括本地 Ollama。

### 第二步：评估队列

导入的简历会进入队列，逐份调用 AI（**串行**，避免触发限流）。

速筛页顶部有队列控制条：

| 按钮 | 行为 |
|---|---|
| 开始评估 | 开始处理待评估的简历；暂停后可继续 |
| 暂停 | 当前这份做完后停下，进度不丢 |
| 重试失败 | 把评估失败的简历重新排队 |

**两种使用方式**：

- **自动开始**（默认）：导入后立即开始评估，多份简历自动排队
- **手动开始**：关闭「导入后自动开始评估」后，导入的简历停在待评估，你可以在合适的时候点「开始评估」

队列状态实时显示：正在处理谁、已完成几份、剩余几份、进度条。

### 失败处理

- 单份失败不会中断队列，其余继续
- 失败原因记录在简历上（卡片显示"评估失败"徽标，悬停看详情）
- **失败不会自动重试**，避免接口持续故障时无限重试；点「重试失败」才重新排队
- 常见错误已翻译成人话：Key 无效、限流、超时、无法连接

### 改岗位或改规则后

分数完全由 AI 产出，所以改动岗位或筛选规则不会自动生效，需要重新问一次 AI。

- 切换岗位后，点设置页或 AI 面板的 **「全部重新评估」** 把简历重新排队
- 然后点 **「开始评估」** 执行（队列空闲时也会自动接着跑）
- 只想重试失败的简历，点 **「重试失败」** 即可

### 进度与中断

- 暂停或关闭应用时，正在处理的那份会退回待评估，下次继续
- 队列状态存在数据库的 `eval_status` 列，重启应用后未完成的任务仍在

## 对外审查 API

应用会在 `127.0.0.1:8765` 提供一个本地 JSON API，供**外部** AI / Agent 读取评分结果并回写结论。

> **默认关闭**。需要在设置页点「启动 API」才会运行；勾选「随应用自动启动」后下次开机自动起。

**安全设计**：

- 只监听 `127.0.0.1`，不接受外部网络访问
- 所有接口（除 `/health`）必须携带启动时随机生成的令牌
- 默认**不返回**简历原文与联系方式
- 令牌可在设置页重置

### 获取令牌

打开 **设置 → 本地 AI 审查 API**，页面会显示当前端口与令牌。也可用 `curl` 检查：

```bash
curl http://127.0.0.1:8765/health
# {"ok": true, "app": "resume-gacha", "version": "2.1.0", "auth_required": true}
```

### 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查（无需令牌） |
| GET | `/` | 接口说明 |
| GET | `/candidates` | 候选人列表，含评分、优缺点、维度理由 |
| GET | `/candidates/{id}` | 单份完整详情（含简历分段原文） |
| GET | `/stats` | 统计与速筛进度 |
| GET | `/config` | 当前岗位、阈值与筛选规则 |
| GET | `/export?format=json\|csv\|md` | 导出并返回文件路径 |
| POST | `/review` | 回写单份审查结论 |
| POST | `/review/batch` | 批量回写 |

**查询参数**：`rarity=SSR|SR|R`、`min_score=70`、`pending=1`、`sections=1`、`limit=100`

### 调用示例

```bash
TOKEN="你在设置页看到的令牌"

# 1. 读取待审简历
curl -H "X-API-Token: $TOKEN" \
  "http://127.0.0.1:8765/candidates?pending=1&limit=5"

# 2. 读取单份详情
curl -H "X-API-Token: $TOKEN" \
  "http://127.0.0.1:8765/candidates/1"

# 3. 回写 AI 审查结论
curl -X POST -H "X-API-Token: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"id":1,"verdict":"liked","note":"AI 复核：技能与岗位高度匹配"}' \
  "http://127.0.0.1:8765/review"
```

### 返回结构（节选）

```json
{
  "id": 1,
  "name": "张伟",
  "score": 91.2,
  "rarity": "SSR",
  "status": "pass",
  "review_verdict": "",
  "years": 12.1,
  "degree": "本科",
  "school": "浙江大学",
  "school_tier_label": "C9",
  "detected_role_label": "后端开发",
  "news_flash": "整体竞争力强，建议优先沟通。技能栈扎实，命中 19 项…",
  "strengths": ["技能栈扎实，命中 19 项（微服务、Java、Redis、Kafka）", "…"],
  "weaknesses": ["未发现明显短板，建议面试进一步确认"],
  "dimensions": [
    {"key": "skill", "label": "技能匹配", "score": 100, "weight": 0.27,
     "reason": "识别到 19 项技能，覆盖 6 个类别…"}
  ],
  "skills": [{"name": "微服务", "category": "后端与架构", "count": 5}]
}
```

> 设计意图：AI 拿到的是**已经算好的结构化结论**，不需要重新解析简历，也拿不到隐私原文。AI 的职责是二次复核与判断，而不是替代评分。

## 评分方式：完全由 AI 判断

**没有规则引擎。** 早期版本用加权规则打分（技能命中数、年限曲线、院校层级等），
但机械规则容易误判——比如把"在清华工作"当成"清华毕业"，或者把项目写得少的人直接判低分。
现在分数、等级、优缺点、筛选结论全部由 AI 产出。

### AI 拿到什么

每次评估会把以下内容写进提示词：

| 内容 | 说明 |
|---|---|
| 岗位画像 | 该岗位看重的核心能力（带权重），或你自定义的关键词 |
| 筛选规则 | 最低分、最低年限、最低学历、必备关键词、淘汰关键词 |
| 稀有度阈值 | SSR / SR 的分界线 |
| 评分维度 | 技能、经验、学历、项目、岗位匹配五个维度及定义 |
| 简历全文 | 最多 16000 字符 |

### AI 返回什么

```json
{
  "overall_score": 78.5,
  "status": "pass | flagged | rejected",
  "dimensions": {
    "skill": {"score": 85, "reason": "引用简历中的具体依据"},
    "experience": {"score": 80, "reason": "..."},
    "education": {"score": 75, "reason": "..."},
    "project": {"score": 78, "reason": "..."},
    "job_match": {"score": 76, "reason": "..."}
  },
  "strengths": ["优势1", "优势2"],
  "weaknesses": ["不足1"],
  "summary": "一句话结论",
  "screen_reasons": ["不满足的规则"]
}
```

**稀有度由本地按阈值换算**，不采信模型自己填的 `rarity` 字段，避免模型随意定级。

### 客观信息仍由本地解析

姓名、手机号、邮箱、教育经历、工作年限这些**展示用**信息仍由本地解析器提取
（不参与打分）。这样即使 AI 漏答，卡片上也能看到院校全名与联系方式。

### 没有 AI 就不能用

未填写 API Key 时：

- 导入的简历会停在「待评估」，分数为 0
- 点「开始评估」会提示去设置页配置
- 所有需要分数的地方（速筛、统计平均分）都不显示假数据

## 学历与院校分层

学历本身不分档加减分（评分交给 AI），但院校层级仍由本地识别，用于**展示**：

| 层级 | 示例 |
|---|---|
| C9 | 清华、北大、浙大、复旦、上交、中科大、南大、哈工大、西交 |
| 985 | 电子科技大学、武汉大学、中山大学… |
| 海外名校 | 麻省理工、斯坦福、牛津、剑桥、港大… |
| 211 | 南京理工、暨南大学、上海财经… |
| 双一流 | 上海科技、南方科技、宁波大学… |
| 海外院校 | 香港城市、曼彻斯特、首尔大学… |
| 普通本科 | 其他大学/学院 |
| 专科院校 | 职业技术学院、职业学院 |

层级标签会显示在卡片和详情里，AI 评估「教育背景」维度时也能看到学历与院校。

**学历识别做了防误判**：

- **只从「教育背景」章节读取**。简历没有教育章节时，不会拿整份简历去猜——
  否则「在清华大学工作」会被误当成「清华毕业」
- 没有教育章节时，只采信同时含「学历词 + 院校/毕业/专业」且不含「负责/主导/公司」等
  工作描述词的行；项目经历章节里的校名也不会被当成学历
- 跳过"本科及以上""要求本科"这类**招聘要求**行
- 多段学历取最高（本科 + 硕士 → 硕士）

> 院校名单不追求穷尽，见 `app/schools.py`。

## 稀有度阈值

| 稀有度 | 默认阈值 | 含义 |
|---|---|---|
| SSR | ≥ 82 | 优先沟通 |
| SR | ≥ 66 | 值得进一步了解 |
| R | < 66 | 备选或暂不推进 |

在 **设置 → 稀有度阈值** 用滑块调整，下方实时预览三档区间。滑块已针对浅色主题做了高对比度处理（8px 轨道 + 蓝色填充 + 白色描边）。

> 建议：先跑一批真实简历看分布，再微调。SSR 超过 20% 就上调 3–5 分，全是 R 就下调。

## 从源码构建便携版

```bash
# 一键构建：PyInstaller 目录版 → 组装便携目录 → 压缩 zip
.venv/Scripts/python.exe build.py
```

产物：

```
release/
├── ResumeTap/                      ← 便携版根目录，可直接运行
│   ├── ResumeTap.exe
│   ├── _internal/                  运行依赖
│   ├── ui/  assets/  samples/      可直接查看修改的资源
│   ├── data/                       空的 data 目录（首次启动自动填充）
│   ├── config.example.yaml
│   ├── README.txt
│   └── LICENSE
└── ResumeTap-v3.1.1-win64.zip      ← 上传 GitHub Release 用这个
```

构建脚本自动完成：

1. 检查/生成图标与示例简历
2. 清理旧产物
3. PyInstaller `--onedir` 打包到 `release/ResumeTap/`
4. 把 `ui/`、`assets/`、`samples/` 复制到便携目录（用户可见、可改）
5. 创建空的 `data/` 结构，写入 `README.txt`、`config.example.yaml`、`LICENSE`
6. **清掉本地测试产生的 `config.yaml` / `data.db`**，保证发布包是干净的首次启动状态
7. 压缩为 zip（解压后得到 `ResumeTap/` 顶层目录）

### 为什么不打包成单个 exe

单文件 exe 每次启动都要把 40 MB 解压到临时目录，冷启动 3-4 秒；
而且它不适合做便携版——真正需要"带走全部数据"时，目录结构才直观可控。
如果确实需要单文件：

```bash
.venv/Scripts/python.exe build.py --onefile
```

### 其他选项

```bash
.venv/Scripts/python.exe build.py --no-zip    # 只生成目录，不压缩
.venv/Scripts/python.exe build.py --keep      # 保留旧的 build/release
```

### 发布到 GitHub

前置：安装 [gh CLI](https://cli.github.com/) 并 `gh auth login`（git push 凭证由它提供）。

```bash
.venv/Scripts/python.exe tools/release.py
```

脚本会：`git push` 源码 → 创建/更新对应版本的 Release →
上传 `ResumeTap-v<版本>-win64.zip`。

只做其中一步：

```bash
.venv/Scripts/python.exe tools/release.py --skip-code    # 只上传 zip
.venv/Scripts/python.exe tools/release.py --skip-asset   # 只推源码
```

### 调整版本号

版本号只在 `app/paths.py` 的 `APP_VERSION` 一处维护，构建脚本与发布脚本都会读取它。

### 数据目录（便携）

数据默认放在**程序目录下的 `data/`**：

```
ResumeTap/
└── data/
    ├── config.yaml     # 你的配置（API Key、岗位、筛选规则、阈值）
    ├── data.db         # 简历库与 AI 评估结果
    ├── resumes/        # 导入的简历文件副本
    ├── exports/        # 导出的 CSV / JSON / Markdown
    └── logs/app.log    # 运行日志（自动轮转、已脱敏）
```

**定位规则**（按优先级）：

1. 环境变量 `RESUME_TAP_DATA_DIR` 指定的目录
2. 打包版：`<程序目录>/data`（便携模式）
3. 源码运行：`<项目>/.devdata`
4. 程序目录不可写时（例如装在 `C:\Program Files`）→ 回退 `%APPDATA%\ResumeGacha`

从旧版（v3.0 及更早）升级时，首次启动会自动把 `%APPDATA%\ResumeGacha` 里的
配置与数据库**复制**到新的 `data/` 目录，源目录保留不删。

## 常见问题

**双击 exe 没反应 / 闪退？**

查看 `data\logs\app.log`（便携模式）；如果程序目录不可写、数据回退到了用户目录，则看 `%APPDATA%\ResumeGacha\logs\app.log`。常见原因：缺少 WebView2 运行时（应用会弹窗提示安装）；被杀毒软件拦截（添加信任，或用 `--onedir` 构建）。

**API 的 fetch 在页面上失败？**

页面自身不需要调用 API（界面直接走进程内桥接）。API 是给**外部**程序用的，请用 `curl` 或 Python `requests` 从命令行/脚本调用。浏览器页面因 `file://` 的 CORS 限制无法直接 fetch。

**AI 能拿到简历原文吗？**

默认不能。`/candidates` 只返回结构化评分与理由；`/candidates/{id}` 返回分段文本（教育/工作/项目/技能），但不含联系方式与完整原文。只有开「保存简历原文」并在详情页手动展开才能看到完整原文（界面内）。

**支持 `.doc` 或扫描版 PDF 吗？**

不支持 `.doc`/`.wps`（另存为 `.docx` 或 PDF）。扫描件 PDF 只有图片，会提示"未从 PDF 中提取到文字"，需要先 OCR。

**为什么某份简历分数偏低？**

打开详情看五维明细与 AI 给出的「不足」项。通常是简历里没有写清楚工作年限、项目成果或技能栈，AI 只能按有限信息判断——补充量化结果会明显改善分数。

**改了阈值，为什么分数没变？**

阈值只影响**稀有度分级**（SSR/SR/R），不改变 AI 给的综合分。想改变分数只能改岗位/筛选规则后重新评估。

**速筛标记错了怎么办？**

完成页有「重新开始速筛」，或在简历库点开详情重新评价。重新排队评估不会清除人工评价。

**导入重复文件会怎样？**

按内容 SHA-256 去重，重复导入自动跳过并提示。

**换电脑怎么迁移？**

便携版：直接复制整个 `ResumeTap` 文件夹到新电脑，数据在 `data/` 内一并带走。

如果程序装在无写入权限的位置（数据落在 `%APPDATA%\ResumeGacha`），
把那个目录一起复制过去即可。

## 隐私说明

- **全程本地**：不发起网络请求（API 是本机回环），不依赖 CDN。
- **原文可控**：可关闭原文保存（`privacy.store_raw_text: false`）。
- **日志脱敏**：只记录文件名、数量、异常类型，不记录正文、手机号、邮箱。
- **API 隔离**：仅 `127.0.0.1` + 令牌鉴权，默认不返回联系方式与原文。
- **导出安全**：CSV 对以 `= + - @` 开头的字段做公式注入转义。
